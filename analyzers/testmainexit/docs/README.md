An `analysis.Analyzer` that reports a `TestMain` function that runs the tests
and returns.

```go
func TestMain(m *testing.M) {
    m.Run() // TestMain does not exit with the code from m.Run
}
```

The testing package says `M.Run` returns "an exit code that may be passed to
`os.Exit`", and that "if `TestMain` returns, the test wrapper will pass the
result of `M.Run` to `os.Exit` itself"
([testing.M.Run](https://pkg.go.dev/testing#M.Run)). The go command generates
that wrapper from Go 1.15 on. An earlier one exits 0 whatever the tests did, so
the function has to call `os.Exit` itself.

The rule is adapted from staticcheck's `SA3000`, which reports "`'TestMain'`
doesn't call `'os.Exit'`, hiding test failures".

## Checks

The gate is the module's `go` directive: a file is reported only when it is
checked against Go 1.14 or earlier. A file that declares no version is checked
against the whole language, where the wrapper exists, and is left alone.

The wrapper is generated by the toolchain that builds the test binary, not by
the version in `go.mod`, so a module that declares Go 1.14 and is tested with a
newer toolchain exits with the code from `m.Run` already, and is still
reported.

The function has to be the test binary's entry point: named `TestMain`, with no
receiver, and one parameter of type `*testing.M`. The body has to call `m.Run`,
and the parameter has to be the receiver of that call.

A call to `os.Exit` anywhere in the body settles the rule, including one inside
a function literal. The rule reads the function's own body, so a call to a
helper that exits is not seen and the function is reported even though the exit
happens. A body that reports the code another way, by panicking on it, say, is
reported too: the rule looks for the call to `os.Exit`.

## Fixes

A body whose only `m.Run` call is its last statement becomes
`os.Exit(m.Run())`, under the import name of the `os` package, and a file with
no `os` import takes one. The fix changes behavior on purpose: the exit code
reaches the caller.

The exit skips whatever the function would still do, so the fix is withheld
after a `defer` in the function, before a statement that follows the call, and
where the call's result is kept. It is withheld too where there is no name to
write: a dot or blank import of `os`, or something else holding `os` at the
call. The function is reported in every one of those cases.

## Usage

```sh
go get -tool lesiw.io/tools/analyzers/testmainexit/cmd/testmainexit
go tool testmainexit ./...
```

Or run it as part of the suite:

```sh
go tool lesiw.io/tools/cmd/vet -testmainexit ./...
go tool lesiw.io/tools/cmd/fix -testmainexit ./...
```
